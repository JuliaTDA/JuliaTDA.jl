# JuliaTDA performance roadmap

**First competitive target:** exact Vietoris–Rips barcodes over F₂ on sparse Euclidean clouds and on dense inputs through H₂ and H₃. Fix the Mapper nerve race first. For Rips, the largest measured opportunities are graph construction on sparse inputs and column assembly and reduction in higher dimensions.

## Baseline · 25 November 2026

Times are medians of five warmed runs on an Intel Core i9-13980HX with Julia 1.12.5 and one BLAS thread. Core Julia PH used one Julia thread. The snapshot includes working-tree backends. For comparisons on shared distance matrices and the image, the interval endpoints matched exactly in every dimension. The two torus construction paths agreed within an absolute tolerance of 10⁻¹². [Benchmark scripts, source snapshot, versions, and raw results](docs/maintenance/2026-11-25-performance-evidence.zip)

| Workload | Julia baseline | Alternatives measured on the same input |
|---|---:|---|
| First 5,000 points of `torus10k`, radius 0.15, through H₂ | 335 ms with `sparse=true`, 577 MiB allocated | Indexed radius graph **11.3 ms**, 9.9 MiB allocated. Graph construction alone fell from 316 to 4.2 ms for 12,886 edges. |
| `klein500`, Float32 distance matrix, threshold 1.5, through H₂ | 526 ms cohomology | Julia edge collapse **88 ms**, RedZeD 184 ms. giotto-ph with edge collapse took 53 ms on either one or eight threads. |
| `o3_1024`, Float32 distance matrix, threshold 1.8, through H₃ | 1,613 ms cohomology | Julia RedZeD **639 ms**, edge collapse 946 ms. giotto-ph with edge collapse took 184 ms on one thread and **111 ms** on eight. |
| 256 × 256 crop of `lena1024`, vertex lower-star H₀/H₁ | 19.9 ms cohomology | Julia cubical union-find **9.45 ms**. CubicalRipser took **8.81 ms** with locations. |
| Mapper `SimpleNerve`, sparse 512-set cover | 19.6 ms on eight threads, 126 MiB allocated | Serial point-to-cover membership index **0.30 ms**, 1.1 MiB allocated. Both produced the same 511 edges. |
| Scale-space Gram matrix, 48 diagrams × 80 finite intervals, Float64 | 61.2 ms serial | Threaded prototype **15.1 ms** on eight threads. RTX 4070 Laptop GPU prototype **2.57 ms** including both transfers, plus 0.03 ms to pack inputs. Maximum absolute error was 1.14 × 10⁻¹³. |

## Work to track

The [verification report](docs/maintenance/2026-11-25-roadmap.md) describes the implementations and acceptance checks. The [benchmark commands](benchmarks/performance/README.md) reproduce the workload sweeps. The related release milestones are P4.1, P4.2, P4.4, and P4.5 in the [ecosystem roadmap](ROADMAP.md).

### First priorities

- [x] **Fix threaded nerve construction — TDAmapper.** Eight threads missed edges in 91 of 100 runs on a 96-set cover where every set shares one point. Threads can overwrite each other's bits in the shared `BitMatrix`. Build the simple nerve from point memberships and audit the minimum-count, Jaccard, and percentage nerves for the same race. Verify the complete graph has all 4,560 edges on repeated threaded runs, compare each nerve against a serial reference, and rerun the sparse-cover benchmark. **25 November 2026.** All four nerve implementations use point memberships. The 512-set fixture fell from 14.8 ms to 0.080 ms; all 100 complete-cover checks passed. [Benchmark code](benchmarks/performance/sweeps.jl) · [Measurements](docs/maintenance/2026-11-25-roadmap-data/nerve.csv)
- [x] **Select indexed Rips construction for eligible clouds — TDARipserer.** The explicit `radius_graph=true` path provides the baseline. Sweep point count, ambient dimension, and retained edge density to find where indexing wins. Verify any automatic choice against the explicit paths, including thresholds at floating-point boundaries, and keep a way to select the backend. **25 November 2026.** Opt-in `radius_graph=:auto` chose indexing in 10 of 48 cases. The 4,096-point 4D sparse fixture fell from 329 to 7.47 ms. [Benchmark code](benchmarks/performance/sweeps.jl) · [Measurements](docs/maintenance/2026-11-25-roadmap-data/radius.csv)
- [x] **Reduce dense H₂/H₃ work — TDARipserer.** On `klein500`, the default engine assembled 1.58 million H₂ columns for three H₂ intervals. Assembly took 90 ms, and sorting and reduction took 395 ms. Profile the edge collapser's backward scans and prototype parallel apparent-pair discovery before the shared pivot reduction. Report stage and end-to-end timings on both dense fixtures, with matching endpoints and the same requested output. Edge collapse and RedZeD traded places between the two fixtures. [giotto-ph](https://github.com/giotto-ai/giotto-ph) · [Ripser++](https://github.com/simonzhang00/ripser-plusplus) **25 November 2026.** Parallel apparent-pair discovery and backward-scan profiling are complete. O(3) H₃ assembly was 355 ms and discovery plus reduction was 638 ms, compared with 329 ms and 1,129 ms for the reference stages. [Benchmark code](benchmarks/performance/bench.jl) · [Measurements](docs/maintenance/2026-11-25-roadmap-data/o3.jsonl)
- [x] **Establish a repeatable cross-framework benchmark — JuliaTDA.** Start with the sparse torus, Klein, and O(3) fixtures above, then sweep sizes and thresholds. Record revisions, hardware, field, precision, requested metadata, thread counts, cold and warm wall time, and peak RAM. For GPU runs, include peak VRAM and transfer time. Compare full barcode multisets, including essential intervals. Publish results by workload so another machine can reproduce each claim. **25 November 2026.** The fixture sweeps cover torus, Klein and O(3), with full barcode comparison and per-process timing and RSS. The eight-thread giotto-ph collapse arm showed intermittent O(3) mismatches, which the runner now records per sample. [Benchmark code](benchmarks/performance/run.py) · [Measurements](docs/maintenance/2026-11-25-roadmap-data/giotto-collapse-stability.json)

### Threads, GPU, and follow-up workloads

- [x] **Thread diagram kernel matrices — TDAPersistenceDiagrams.** Distribute independent diagram pairs across workers. Match the serial result and benchmark across diagram counts, interval counts, and thread counts to find the smallest batch that benefits. **25 November 2026.** Use `kernel_matrix(...; threaded=true)`. The 48-diagram ragged corpus with up to 80 intervals fell from 29.8 to 9.72 ms. [Benchmark code](benchmarks/performance/sweeps.jl) · [Measurements](docs/maintenance/2026-11-25-roadmap-data/gram-8.csv)
- [x] **Evaluate an optional GPU scale-space kernel — TDAPersistenceDiagrams.** Extend the measured prototype to variable-length, empty, and essential-interval inputs. Compare Float64 results to the CPU implementation and report end-to-end timings against threaded CPU across batch sizes. GPU persistent homology needs its own benchmark, beginning with apparent-pair discovery. **25 November 2026.** The Float64 prototype matched CPU results across 15 ragged corpora. At 48 diagrams with up to 80 intervals, it took 1.42 ms including transfers, plus 0.073 ms for packing. The separate apparent-pair prototype matched all sampled H₂/H₃ columns. [Benchmark code](benchmarks/performance/device.py) · [Measurements](docs/maintenance/2026-11-25-roadmap-data/gpu-gram.jsonl)
- [x] **Benchmark cubical persistence at image and volume scale — TDARipserer.** Extend the 2D result to larger images and 3D volumes. Time grid construction and each requested homology dimension, especially the 3D H₁ cohomology path. Compare endpoints, boundary conventions, output metadata, and peak memory with CubicalRipser. **25 November 2026.** CubicalRipser matched every endpoint through 1,024² images and 64³ volumes. The 64³ Julia union-find run took 264 ms, with about 107 ms in H₁ reduction. [Benchmark code](benchmarks/performance/bench.jl) · [Measurements](docs/maintenance/2026-11-25-roadmap-data/volume.jsonl)
- [x] **Parallelize permutation replicates — PersistenceInference.** The current loop recomputes PH for two groups per permutation. Generate sample indices in seeded order and use a bounded worker pool. Check the full null distribution and p-value against serial execution, then measure time and peak memory as worker count grows. This candidate comes from source inspection. **25 November 2026.** One to eight workers reduced 442 ms to 96.3 ms with the same seeded null distribution and p-value. [Benchmark code](benchmarks/performance/sweeps.jl) · [Measurements](docs/maintenance/2026-11-25-roadmap-data/permutation.csv)

Exercise ties and multiway saddles against explicit expected partitions and merge records, then measure scaling on graphs with many accepted merges. This candidate comes from source inspection. **25 November 2026.** Union-find reduced the 32,768-vertex path from 121 to 3.40 ms with identical merge records and partition.
