Choosing a workflow

Start from the question you want to answer. Several packages can analyze the same data while producing different objects.

Choose a package, not necessarily the entire umbrella

using JuliaTDA is convenient for combining methods. To keep an application focused, import just the owning package:

PackageOwnsImportant conventions
MetricSpacesPoint representations, distances, neighborhoods, samplers, densities, transformations, Euler/image descriptorsMatrix columns are points; samplers have point and index variants; datasets are a submodule
TDAmapperCovers, refiners, nerves, Mapper results and filter optimizationM.C contains original point indices; strategies live in submodules
TDAplotsMakie figures, layouts, linked explorer and diagram/ToMATo visualsLoad a backend; distinguish point-level and node-level values
ToMAToDensity-mode clustering on a graphGraph radius and density merge threshold have different units

TDARipserer and TDAPersistenceDiagrams are independent experimental forks used as dependencies for PH and diagram tooling. Their package names and UUIDs differ from the original upstream packages. Mixing their diagram types with upstream PersistenceDiagrams types is not a supported substitution.

Keep geometry, metadata and targets separate

Choose geometric columns explicitly. A patient identifier, timestamp or class label can be numeric without being a meaningful coordinate. Keep those columns as metadata for interpretation. Impute or remove missing geometric values before constructing a cloud, preserving the correspondence with rows.

Standardizing coordinates can be useful when units differ; it also changes the geometry. For a learning task, estimate centering/scaling on training data and apply the same transform to validation data. euclidean_space(...; standardize=true) standardizes the table it receives; it does not store a fitted transform for another table.

Inspect duplicate points, finite coordinates and sample sizes before running PH. Duplicate observations affect density estimators and sampling weights, even if a geometric construction collapses some zero-distance relationships.

Learning requires a fitted pipeline

A landscape range, persistence-image grid, ATOL codebook or Gaussian-measure center set inferred from data is a learned parameter. Fit it inside every training fold, then reuse it unchanged on validation observations. Choosing features or Mapper filters after seeing test labels also leaks information.

The nested-CV example illustrates this discipline. For time series, use chronological or blocked splits; overlapping windows are dependent. For subjects with repeated observations, split at the subject level when that matches the intended prediction setting.
