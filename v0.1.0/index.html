JuliaTDA.jl

The umbrella package for Topological Data Analysis in Julia.

New here? Start with Your first shape analysis, an executed circle-to-PH-and-Mapper tutorial. Use Choosing a workflow to pick a method, Reading topological results to interpret it, and Troubleshooting and reproducibility when moving to your own data. Registration is deferred; the installation guide uses local checkouts of the current stack.

What is Topological Data Analysis?

Topological Data Analysis (TDA) is a family of techniques that study the shape of data. Instead of asking only "where are the points?", TDA asks "how are the points connected?" — does the data form loops, branches, clusters, or voids? These questions are answered with tools from algebraic topology, adapted to noisy, finite point clouds. The two flagship techniques are persistent homology, which tracks topological features (connected components, loops, voids) across every scale and records how long each one persists, and Mapper, which builds a compressed graph (or simplicial complex) summarising the data's structure by covering the range of a chosen filter function and gluing together the clusters found in each piece.

TDA shines when the interesting signal in the data is geometric or relational rather than purely statistical: detecting a cyclic process in a time series, finding rare "flares" of anomalous behaviour branching off a dense core, comparing the shape of two datasets, or turning the shape of a point cloud into a fixed-length feature vector for downstream machine learning. The JuliaTDA ecosystem provides a composable, pure-Julia implementation of this whole pipeline.

The ecosystem

A single using JuliaTDA brings the entire stack into scope:

PackageRole
MetricSpaces.jlGeometry foundation: EuclideanSpace, distances, samplers, filters, transformations, and the Datasets submodule
TDAmapper.jlThe Mapper algorithm: mapper, classical_mapper, ball_mapper, plus Tables.jl helpers
TDAplots.jlMakie-based plotting, including the interactive mapper_explorer
TDARipserer.jlPersistent homology: ripserer and several filtrations
TDAPersistenceDiagrams.jlPersistence diagrams, distances, and vectorizations for ML
ToMATo.jlTopological mode-seeking clustering: tomato, proximity_graph
PersistenceInference.jlDiagram resampling, curve confidence bands, explicit-null maximum-persistence and independence tests
MultiparameterPersistence (bundled in lib/)Small-complex exact F₂ Hilbert/Koszul Betti/Euler invariants, signed measures and MLJ features

How the packages compose

MetricSpaces  ──►  TDAmapper  ──►  TDAplots
                                      │
TDARipserer  ──►  TDAPersistenceDiagrams ◄──┘   (TDARipserer re-exports the basics)

ToMATo  (density-based clustering, built on MetricSpaces)
  • MetricSpaces → TDAmapper → TDAplots is the Mapper pipeline. You start from a metric space, run the Mapper algorithm to get a graph, and plot it.
  • TDARipserer → TDAPersistenceDiagrams is the persistent-homology pipeline. TDARipserer computes diagrams; TDAPersistenceDiagrams analyses and vectorizes them. TDARipserer already re-exports the basics of TDAPersistenceDiagrams (birth, death, persistence, barcode, …) as the very same bindings, so there is no name clash.
  • ToMATo is an independent clustering algorithm that also builds on MetricSpaces.
  • PersistenceInference works on point clouds or collections of diagrams, depending on the method. Its tests require an appropriate sampling/null design; see Choosing a workflow.
  • MultiparameterPersistence is a separate package bundled under lib/. It supplies reference algorithms for finite two-parameter grids rather than a general multiparameter barcode.

Name resolution

Both MetricSpaces and ToMATo export a knn_density. Under using JuliaTDA the unqualified name resolves to MetricSpaces' density filter; ToMATo's clustering variant stays reachable as JuliaTDA.ToMATo.knn_density. Similarly, eccentricity and center (also exported by Graphs) are pinned to their MetricSpaces meaning.

Tables.jl, built in

Because JuliaTDA depends on Tables directly, TDAmapper's Tables.jl extension is always active. You can build a metric space straight from a NamedTuple, a DataFrame, or any Tables.jl source with euclidean_space, and summarise a Mapper's nodes against the original table with node_statistics.

Installation

Development install (now)

Registration is deferred. From a local JuliaTDA.jl checkout, develop the bundled multiparameter package and the sibling repositories in the same call:

using Pkg
Pkg.activate(".") # run from a local JuliaTDA.jl checkout
Pkg.develop([
    PackageSpec(path = "lib/MultiparameterPersistence"),
    PackageSpec(url = "https://github.com/JuliaTDA/MetricSpaces.jl"),
    PackageSpec(url = "https://github.com/JuliaTDA/TDAmapper.jl"),
    PackageSpec(url = "https://github.com/JuliaTDA/TDAplots.jl"),
    PackageSpec(url = "https://github.com/JuliaTDA/Ripserer.jl"),
    PackageSpec(url = "https://github.com/JuliaTDA/PersistenceDiagrams.jl"),
    PackageSpec(url = "https://github.com/JuliaTDA/ToMATo.jl"),
    PackageSpec(url = "https://github.com/JuliaTDA/PersistenceInference.jl"),
])
Pkg.instantiate()

For the current sibling checkouts (including unpublished changes), follow the isolated-environment instructions in Your first shape analysis. The umbrella requires Julia 1.10 or later. A plotting backend is separate; using JuliaTDA does not activate one.

Registry install (later)

Once the ecosystem is registered this becomes a single line:

using Pkg; Pkg.add("JuliaTDA")

Worked examples

  • Mapper exploration — load a table, choose a filter, run Mapper, colour by the filter, and use node_statistics to find what makes a flare special; plus the interactive mapper_explorer.
  • Persistent homology for ML — point clouds → ripserer → diagram plots → Landscape/PersistenceImage feature matrix ready for a classifier.
  • ToMATo clustering — a noisy multi-blob dataset → density → proximity_graph → tomato → a scatter coloured by cluster.
  • P2 expansion workflows — Euler descriptors, multiparameter invariants, optimal chains, time series, cubical images and trainable Mapper filters.
  • Inference, differentiable PH, descriptors and tuning — population mean bands and an introduction to optional learning integrations.
  • Changing shapes and comparing diagrams — landmarks, cell edits, filtration-value updates, diagram means and kernels.

Each package owns its complete API documentation. The umbrella focuses on how the pieces compose and on interpretation of the resulting objects. Small documentation examples demonstrate behavior; they do not replace calibration or sensitivity checks for a scientific study.
