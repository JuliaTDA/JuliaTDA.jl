# Changing shapes and comparing diagrams

The umbrella also composes algorithms supplied by its PH and diagram
dependencies. This page is a small executable orientation to those APIs;
their full algorithm manuals remain in TDARipserer and TDAPersistenceDiagrams.

## Use landmarks when the cloud is large

Witness constructions use a smaller landmark set as vertices and the full
cloud as geometric witnesses. They can avoid the full cloud's square distance
matrix, although landmark count still controls combinatorial cost.

```@example changing_shapes
using JuliaTDA
angles = range(0, 2π; length = 65)[1:64]
points = [[cos(t), sin(t)] for t in angles]
landmark_ids = [1, 17, 33, 49]
filtration = LazyWitness(points, landmark_ids; nu = 1)
witness_diagrams = ripserer(filtration; dim_max = 1)
(landmarks = filtration.landmarks, loop_intervals = length(witness_diagrams[2]))
```

Filtration vertex `i` refers to the `i`-th selected landmark, whose original row
is `landmark_ids[i]`. For the matrix constructor, rows are witnesses and
columns are landmarks. A witness barcode need not equal the full-cloud Rips
barcode. Compare landmark choices and retain provenance for interpretation.

## Cell additions and removals: zigzag

Ordinary persistence grows a complex. A changing observation window can also
remove cells. Zigzag persistence supports arrows in both directions. Supply
valid cell edits: add faces before cofaces and remove cofaces before faces.

```@example changing_shapes
events = [
    :add => (1,),
    :add => (2,),
    :add => (1, 2),
    :remove => (1, 2),
    :remove => (2,),
]
zigzag = zigzag_persistence(events; dim_max = 0)
[(birth(interval), death(interval)) for interval in zigzag[1]]
```

Endpoints are **state indices**, not geometric distances. An open interval at
the end of a stream is right-censored. For streaming use,
`ZigzagPersistence` supports `push!` with `ZigzagEvent` and inspection through
`zigzag_diagrams`.

## Fixed cells with changing values: vineyards

A vineyard follows persistence when filtration values move but the complex
stays fixed. This differs from inserting or deleting cells.

```@example changing_shapes
vineyard = Vineyard([(1,) => 0.0, (2,) => 0.0, (1, 2) => 1.0]; dim_max = 0)
update_vineyard!(vineyard, Dict((1, 2) => 2.0); time = 1.0)
[(birth(interval), death(interval)) for interval in vineyard_diagrams(vineyard)[1]]
```

Face values must not exceed coface values. Vines track endpoint paths through
adjacent order changes; tied crossings can admit more than one continuation.
Large reorderings can cost more than fresh PH, so benchmark the actual workload.

## Average diagrams with a geometric objective

Diagrams have varying numbers of intervals; coordinatewise arithmetic means
require a matching first. A Fréchet mean minimizes the weighted squared
Euclidean Wasserstein objective with diagonal matching available.

```@example changing_shapes
diagrams = [PersistenceDiagram([(0.0, 2.0)]; dim = 1),
            PersistenceDiagram([(0.0, 4.0)]; dim = 1)]
result = frechet_mean(diagrams)
(mean_intervals = [(birth(i), death(i)) for i in result.diagram],
 objective = result.objective, converged = result.converged)
```

The mean of these two aligned intervals is `(0, 3)` and the objective is `1`.
For three or more input diagrams, convergence is a diagnostic of the chosen
optimization procedure, not a global-optimum certificate. Inspect diagnostics
and initializations. Essential intervals require compatible cardinalities.

## Compare a collection through kernels

```@example changing_shapes
gram = kernel_matrix(PersistenceScaleSpaceKernel(), diagrams)
size(gram)
```

A Gram matrix has one row/column per diagram. Kernel scale, weights and
essential-interval policies are part of the feature definition. Fit or tune
them within training folds when using the matrix in supervised learning.
Persistence scale-space and weighted Gaussian kernels ignore essential
intervals; custom-weight stability needs the assumptions stated in the owning
package's kernel manual.
